## 2. Project Requirements & Architecture Summary

### Core Purpose & Constraints
- **Target Audience:** African bioinformatics students and researchers (e.g., personas Tunde and Chidi) working on low-spec hardware (~4 GB RAM laptops, mobile devices), on metered data bundles (~1.5 GB), and over unstable power and internet.
- **Client Execution:** WebAssembly in browser Web Workers (Pyodide for Python, WebR for R, Biowasm for CLI utilities like `samtools`). Zero cloud sandboxes or Docker containers.
- **In-Browser Verification:** Deterministic checks (Output, Property, Method checks) run inside the client worker in under 3 seconds without human grading.
- **Resilience & Caching:** IndexedDB autosaves work every 5 seconds. Replays run on clean exits, and prompt for restore on tab crashes. Opened steps reopen offline within 24 hours.
- **Business Model:** Freemium. Single PRO time-pass plan paid via Flutterwave in Naira (manual renewal, no recurring card debits). Paid content is strictly guarded.

### The Five Learning Features (v1 Scope)
1. **Guided Step Page:** CodeMirror 6 editor, terminal/console output, Markdown instructions, check runner, hint ladder. Stacks/tabs gracefully on smaller displays.
2. **Check My Work:** Instant client-side automated grading with plain English feedback and localized error pattern matching.
3. **Autosave and Resume:** Snapshot & command log storage in IndexedDB, server sync with `baseRevision` optimistic locking and conflict resolution.
4. **Hint Ladder & AI Mentor:** 3 authored hints (gentle nudge -> concept reference -> shape of action). 4th rung is a Socratic RAG mentor using pgvector that **withholds final answers and code commands**, backed by hard daily token/cost ceilings and output filters.
5. **Progress Map:** Visual track of case studies with statuses (`NOT_STARTED`, `IN_PROGRESS`, `PASSED`, `SKIPPED`) and access locks for free users.

### Supporting Server Requirements
- **Authentication:** Passwordless 6-digit email code (10-minute expiry, 3 requests/hour limit, 5-try lockout). 30-day JWT sessions checked in Node API routes.
- **Access Guard (`assertStepAccess`):** Mandatory server guard across `/api/steps/:id/bundle`, `/api/steps/:id/datasets`, `/api/mentor`, and `/api/sync`.
- **Payments:** Flutterwave redirect checkout. Idempotent fulfillment via `fulfillPayment(reference)` verified directly with Flutterwave API. Stacking time passes.
- **Content Importer:** Validates content, splits markdown into headings/chunks (<300 tokens), embeds with 768-dimension vectors, writes `ContentChunk` via raw SQL.
- **Privacy & NDPA 2023:** "Delete my data" cascades all user data while detaching user references on payment rows for accounting compliance.

### What Version One Deliberately Excludes
- No certificates, leaderboards, user forums, or live chat.
- No video streaming or cloud execution.
- No custom user file uploads or patient genomic data.
- No auto-renewing subscriptions, coupons, or multi-seat licenses.
- No admin dashboard screen (owner uses CLI scripts: `grant-pro`, `revoke-pro`, `mark-refunded`, `list-pending`).

## 3. Design System & Styling Rules Summary

Per [main-tokens.css](file:///c:/Users/Chijioke%20Uhegwu/Desktop/Product%20Folder/Nucleobridge/task-01-design-system/main-tokens.css), [README.md](file:///c:/Users/Chijioke%20Uhegwu/Desktop/Product%20Folder/Nucleobridge/task-01-design-system/README.md), and [interview-answers.md](file:///c:/Users/Chijioke%20Uhegwu/Desktop/Product%20Folder/Nucleobridge/task-01-design-system/docs/interview-answers.md):

1. **Zero Primitive Exposure:**
   - No raw palette variables (e.g., `--palette-primary-40`, `--neutral-90`) or raw hardcoded hex/RGB/HSL codes in application code or component styles.
   - Only semantic CSS tokens are permitted:
     - Surfaces & Backgrounds: `var(--color-surface)`, `var(--color-background)`, `var(--color-surface-container)`, `var(--color-surface-container-high)`, etc.
     - Content & Text: `var(--color-on-surface)`, `var(--color-on-background)`, `var(--color-on-surface-variant)`.
     - Brand / Actions: `var(--color-primary)`, `var(--color-on-primary)`, `var(--color-primary-container)`, `var(--color-on-primary-container)`.
     - Outlines & Dividers: `var(--color-outline)`, `var(--color-outline-variant)`.
     - Feedback / States: `var(--color-error)`, `var(--color-warning)`, etc.
2. **Dual-Theme Support (Light & Dark):**
   - Identical variable names are mapped under `:root` (Light) and `@media (prefers-color-scheme: dark)` / `[data-theme="dark"]` (Dark).
3. **Typography:**
   - DM Sans font family (`var(--font-family-base)`).
   - Strict 1.5 line-height ratio across 15 standard typography classes:
     - Display: `.text-display-large`, `.text-display-medium`, `.text-display-small`
     - Headline: `.text-headline-large`, `.text-headline-medium`, `.text-headline-small`
     - Title: `.text-title-large`, `.text-title-medium`, `.text-title-small`
     - Body: `.text-body-large`, `.text-body-medium`, `.text-body-small`
     - Label: `.text-label-large`, `.text-label-medium`, `.text-label-small`
4. **Elevation & Shadows:**
   - Brand-tinted shadows: `var(--shadow-soft)`, `var(--shadow-medium)`, `var(--shadow-hard)` (tinted with `#0F6E56`).
5. **Home Screen Specifications:**
   - Exact `100vh` viewport height (`height: 100vh; overflow: hidden;` / `min-h-screen` viewport container).
   - Minimalistic, focused layout featuring responsive navigation header, hero branding, case study track cards with access tier badges, and accessible action buttons.
