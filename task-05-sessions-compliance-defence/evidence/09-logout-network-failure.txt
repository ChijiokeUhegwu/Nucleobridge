=============================================================================

TASK REQUIREMENT & THREAT MODEL:
The Edge Case: A network failure makes the logout request fail on the server
while the interface shows the user as logged out. Their session stays active
and they believe it does not.
Evidence Objective: Reproduce it. Throttle or block the request, capture the
interface claiming success and the session row still present in PostgreSQL.

STEP 3: NAIVE CLIENT-SIDE INTERFACE REACTION (FLAWED LOGIC)
-----------------------------------------------------------------------------
In naive / flawed client implementations:
1. The frontend catch or finally block executes:
   `catch (error) { window.location.assign('/'); }`
2. The browser navigates away from /dashboard to the public landing page (/):
   - Browser URL: https://nucleobridge.org/
   - Visual State: Public landing page displays "Sign In" and "Get Started" buttons.
   - Deceptive Claim: The interface visually claims the user is completely logged out.
3. User Perception:
   The learner believes their authenticated session has ended. They close the laptop
   screen or step away from a public terminal in a university computer lab or cybercafé.

-----------------------------------------------------------------------------
SECURITY ASSESSMENT & ROOT CAUSE
-----------------------------------------------------------------------------
Root Cause:
Optimistic client-side navigation decoupled from server-side confirmation.
When the client navigates away without guaranteeing that the server deleted the
session row and dispatched the clearing Set-Cookie header, the application creates
a false illusion of security while leaving the actual identity boundary open.
