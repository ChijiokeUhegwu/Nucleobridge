1. ARCHITECTURAL FIX OVERVIEW: AUTOMATED BACKGROUND RETRIES & FAIL-SAFE LOGOUT
-----------------------------------------------------------------------------
The fix was implemented across client and server components:

A. Automated In-Flight Background Retries (`src/app/dashboard/page.tsx`):
   1. Transient Network Resilience (Zero-Click Recovery):
      In unstable cellular / metered environments (e.g. mobile tethering in
      Nigeria), network drops frequently occur for split seconds (200ms–800ms).
      Rather than forcing the user to manually click a "Retry" button on a
      temporary jitter, `handleSignOut` executes an automated retry loop:
        - Attempt 1: Immediate dispatch (3500ms timeout)
        - Attempt 2: Auto-retry after 400ms delay
        - Attempt 3: Auto-retry after 800ms delay
      For transient sub-second blips, Attempt 2 or 3 succeeds transparently.
      The user experiences a seamless, single-click signout with zero UI friction.

   2. Deterministic State Machine (Zero False Positives):
      The UI strictly prohibits optimistic redirects. `window.location.assign('/')`
      is ONLY reached if the server returns `response.ok === true` (HTTP 200).

   3. Network Timeout via AbortController:
      Each attempt is protected by an `AbortController` (3500ms timeout) to
      prevent the interface from hanging indefinitely on stalled sockets.

   4. Background Keepalive:
      Configured `keepalive: true` on the `fetch()` call so that the browser
      persists the HTTP dispatch in the background even if the page lifecycle
      is transitioning.

   5. High-Priority Security Warning Fallback (`signOutErrorBanner`):
      If ALL automated attempts fail (indicating a sustained connection outage
      or flight mode), the UI does NOT pretend the user is logged out. Instead,
      it surfaces a high-contrast security warning informing the user that their
      session remains ACTIVE in PostgreSQL and instructs them to close all
      browser windows on shared hardware.

B. Server-Side Route Hardening (`src/app/api/auth/signout/route.ts`):
   Wrapped session invalidation in a defensive try/catch block to ensure that
   server errors return structured HTTP 500 responses rather than unhandled
   crashes, while guaranteeing that valid requests atomically delete the
   session record and dispatch `Set-Cookie: nb_session=; Max-Age=0`.
